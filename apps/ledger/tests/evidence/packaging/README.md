# Offline install-package evidence

All 13 previously frozen native ELF variants produced verified Intel HEX and unsigned install-manager APDU packages: all five models on mainnet/simnet, plus Nano S Plus testnet/testnet2/regtest. This is offline software evidence. No device was loaded, no OS was flashed, no credentials were created, no CA was enrolled, and no vendor authorization or physical compatibility is established. Retail Nano X cannot sideload; its generated bytes are vendor-review artifacts only.

`matrix.json` binds each compact report, exact ELF SHA256 and canonical Ledger application hash. Each `<model>-<network>.json` records effective target/API/flags, name/version, secp256k1 BIP86 prefix, install/icon TLV hashes, source-manifest hash, loader module hashes and every output-file checksum. ELF SHA256 and the Ledger application hash cover different bytes and must not be substituted for one another. Large ELF/HEX/APDU files are not duplicated in this repository; use the replay command below to regenerate them from the corresponding frozen build.

## Verification and limits

- The root `ledger_app.toml` passed Ledger's official manifest parser and resolves `apps/ledger`, Rust and five build targets.
- Eleven focused tests passed locally, including an optional real-ELF check. CI without native artifacts runs the other ten and explicitly skips the real-ELF case.
- The package checker independently validates HEX checksum/entry/load bytes; exact metadata and permissions; APDU header, create parameters, segment order, offsets, CRCs and final commit; all reconstructed image bytes; and the zero-gap-padded application hash against Ledger's canonical `hashApp` result.
- Independent review identified and fixed duplicate `ledger.*` metadata acceptance and incomplete source-map acceptance. Regressions cover identical/conflicting duplicate sections and empty, omitted, additional, invalid or mismatched source hashes. The complete expected build-source key set is required before and after packaging.
- The hardened package generation retained identical ELF, HEX, APDU and application-hash bytes to the earlier valid generation. Only verification/provenance metadata changed.
- The reviewed file-only sink deliberately omits stock cargo-ledger's delete-existing-app step and avoids loadApp's unused manager-key generation. Hardware transports, signing, CA commands and extended/signed commits are not available in this helper. A future authorized replacement install must separately resolve an existing app.
- Effective flags are `0` for Nano S Plus and SDK-added `0x200` settings permission on Nano X/Stax/Flex/Gen5. Exact flags and secp256k1-only mainnet `86'/808276'` or test-network `86'/1'` prefixes are enforced. This confirms packaged requests, not the behavior of installed permissions on hardware.
- Version pinning is not a cross-platform wheel-hash lock or a signed build attestation. Review source/tool provenance and reproduce builds before any release. Official Ledger workflow integration, owner-selected licensing, functional validation, human audit and hardware gates remain pending.

## Independent review and clean preflight

The separate standard-library-only replay passed all 13 package pairs. Its unchanged, portable source is retained at `apps/ledger/tests/package-independent.py` (SHA256 `1576e2760092dab80f719140e190bf75fea7b6545ca36bafbc483d1a4941f600`). Run it without Ledger or project imports:

```sh
python3 apps/ledger/tests/package-independent.py /path/to/package.elf /path/to/package.apdu
```

`independent-review.md`, `independent-matrix.json` and `independent-regressions.json` retain the 13-pair replay and 27 mutation/concurrency checks. A fresh Python 3.12.14 environment installed all 37 exact dependency pins and passed `pip check`; the actual manifest/config/tests commands passed both with native artifacts (11 passes) and in a source-only copy (10 passes, one explicit optional skip). Compact logs are in `clean-environment-checks.txt`. GitHub Actions itself was not dispatched. Original workspace/log paths in the review identify provenance; normal replay requires only the tracked verifier, documented dependencies and an explicitly supplied package.

## Replay

From the repository root, with the documented official ARM toolchain and a fresh Python environment:

```sh
python3 -m venv /path/to/packaging-venv
/path/to/packaging-venv/bin/python -m pip install -r apps/ledger/packaging-requirements.txt
/path/to/packaging-venv/bin/ledger-manifest --check . ledger_app.toml
/path/to/packaging-venv/bin/python -m unittest discover -s apps/ledger/tests -p package_test.py -v
/path/to/packaging-venv/bin/python scripts/ledger-package.py \
  --device nanosplus --network simnet --output /path/to/new-package-directory \
  --objcopy /path/to/official/arm-none-eabi-objcopy
```

Use `nanosplus`, `nanox`, `stax`, `flex` or `apex_p` and the matching existing staged network artifact. No loading command is supplied. Output paths must be fresh; concurrent cooperating writers are serialized and verified output is published as one complete directory. A failed check does not publish a package. Original run outputs are under the shared development evidence workspace; they are not dependencies of the normal replay command.

See [native app and installation documentation](../../../../../docs/firmware.md) and [submission checklist](../../../../../docs/submission-checklist.md) for Nano X, seed/trust, OS-update, privilege and owner/vendor approval boundaries.
