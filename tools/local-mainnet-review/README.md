The local wallet now uses Pearl's actual wallet/Neutrino implementation and native
zkpow/XMSS verifiers at upstream `2f8b770cac8f8b74be05c1fc51c2baeb76ce0701`.

  The existing TypeScript discovery checks accepted the complete result. The
  retained cache occupied approximately 35 MiB; no full block indexer was run.

  The draft was discarded; its input reservation was released, and background
  range recovery preserved the balance and updated confirmations.
- After the final production rebuild and clean local-server restart, Ledger
  Discover restored the remembered account and synchronized without unlocking
  the device. A second unsigned review displayed the exact amount/fee/total and
  the final **Connect Ledger** action. No connection or signing was requested;

No mainnet transaction was signed or broadcast during these checks. Personal
public keys, addresses, transaction IDs, balances and wallet files are omitted.

running wallet's private state is excluded under `.local-light/`.

## Evidence identity and limits

`cold-result.json` binds the original cold-run binary. The stricter peer-tip
readiness predicate was added afterward; `resume-result.json` binds the final
locally built binary and its subsequent real-network checks. These are distinct
artifacts, not a rewritten claim that the final binary performed the cold run.
The retained driver files are exact executed sources, including their original
local paths. Adapt paths deliberately when reproducing; they never take an
actual account or broadcast a transaction. `evidence-sha256.json` binds the
retained records and drivers.

The matched three-file cache copy is recorded in `cache-provenance.json`. It was
made only after clean shutdown, using exclusive regular-file copies. No wallet
database, public-account marker, peer list or process lock was copied into the
new personal wallet. Reopening this cache inherits the trusted pilot's earlier
verification; it does not reverify historical proofs. The new wallet still had
to scan and satisfy current peer/header/filter/wallet readiness.

This is parent-observed integration evidence, separate from the three
[independent AI reviews](../final-local-audit/). It is not a professional human
audit or Ledger approval. The renamed **Pearl 0.1.0** firmware is emulator-tested;
physical installation and an owner-approved funded signature/broadcast remain
manual qualification steps. The earlier physical Pearl Dev account/address and
synthetic-signing checkpoint remains separately recorded.
