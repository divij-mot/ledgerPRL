# Pinned Ledger Bitcoin balance presentation

Read-only source review of Ledger Live desktop 4.23.0 at commit `abed962b08ca4b746f20192b28ce5b6c06a6c6a4`; exact inspected source hashes are in `ledger-bitcoin-balance-source.json`. No user wallet data or network transaction was inspected or changed by this reviewer.

The desktop account headline uses total account balance. `apps/ledger-live-desktop/src/renderer/screens/account/BalanceSummary.tsx` passes the latest history point into `AccountBalanceSummaryHeader.tsx`; that component uses `last.value` at line 41 and passes it to `BalanceTotal` at line 76. `libs/ledger-live-common/src/portfolio/portfolio.ts:getBalanceHistory` sets the current history point from `account.balance` at line 56, rather than `spendableBalance`.

`libs/coin-modules/coin-bitcoin/src/synchronisation.ts:242–264` sums its final unspent UTXOs into transparent balance and uses that as Bitcoin account balance. Unconfirmed UTXOs are not universally excluded; the preceding filtering handles replaced/conflicting unconfirmed transactions. This Bitcoin adapter also sets spendableBalance to balance. Pearl currently has a stricter confirmed-input spending policy; matching the headline does not imply claiming identical unconfirmed-spending behavior.

There is no optimistic arithmetic in the inspected pending-registration path. Desktop `modals/Send/Body.tsx:303–309` registers successful broadcast through `addPendingOperation`. `libs/ledger-wallet-framework/src/account/pending.ts:61–82` copies the account and appends pending operations without changing balance/spendableBalance. Thus the inspected headline continues to use synchronized account balance until that field is updated; adding synthetic change or subtracting an operation from a fresh synchronized UTXO total is not needed for this parity fix and risks double counting.

Recommended narrow change: render Pearl's existing `balances(snapshot).total` as the Balance headline, retain pending/available information separately, and continue using `available` plus current input eligibility checks for payment preparation. This directly handles a synchronized wallet whose remaining funds are unconfirmed change. Parent owns that presentation change and its integrated tests. This is bounded source evidence, not an exhaustive comparison of every Ledger UI variant or a physical-device qualification.
