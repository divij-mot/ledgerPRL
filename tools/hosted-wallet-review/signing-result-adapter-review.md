# Signing attempt result classification review

Reviewed the adapter delta on 2026-10-10. No unresolved P0–P2 issue was established within this bounded source review and mock-transport testing. This is AI review, not a professional security audit or proof about every device/transport behavior.

`SigningFailedWithoutResultError(cause)` is exported through the adapter index. It wraps only the outer `signPrepared` failure path when this invocation has produced no complete independently verified transaction. It retains the original error and, when applicable, device status/instruction. Partial device signatures may exist. The type makes no claim about earlier attempts, external capture, or cancellation of a network transaction. The preceding bare-denial classifier, WeakSet and raw-yield counter were removed.

The enclosing `run` failure path aborts the controller, makes the client terminal, and attempts bounded transport cleanup before propagating active-operation errors. A timed-out close does not prove the underlying connection closed. However, a response arriving after its exchange lost the abort race cannot resume the interpreter or signature callback. A response that wins is processed first, allowing the final signature to become a completed result even when cancellation occurs in that turn. Readiness/pre-cancel admission failures send no command and likewise produce no result for that invocation.

The complete transaction is assigned before invoking its durability callback. Callback rejection or timeout continues to throw `VerifiedSigningResultError` with retained verified bytes. Errors after completion, including final acknowledgement errors or cancellation, continue to return those exact bytes with the existing completion warning. These paths never receive the new no-result type. The host must separately preserve any earlier recovery attempt, staged or saved bytes, and concurrent journal changes; adapter failure classification alone does not authorize releasing arbitrary reservations.

Validation: all **33 adapter tests passed** and adapter TypeScript checking passed. New regressions cover initial and Merkle-continuation denial, identity-read and arbitrary transport/status failures, valid partial signatures, malformed yields, timeout, and cancellation followed by a late valid final wire signature. The late-response test verifies no persistence callback, additional progress, or further APDU after rejection. Existing exact txid/wtxid/raw-byte, final-ACK, cancellation, callback-failure, callback-mutation and durability-timeout assertions remain. No physical device, user state, funds, or real transaction was used.

Evidence: `signing-result-adapter.log`; the two reviewed source hashes are in `signing-result-adapter-source.json`. Companion host integration is separately reviewed by the parent/product agent and is not included in this source snapshot.

## Ledger Bitcoin comparison

Read pinned Ledger Live desktop 4.23.0, commit `abed962b08ca4b746f20192b28ce5b6c06a6c6a4`, from a local checkout and exact public source blobs. `libs/coin-modules/coin-bitcoin/src/signOperation.ts` awaits the full signing result before emitting the signed operation. `libs/ledger-live-common/src/flows/send/hooks/useSendFlowSignatureCore.ts` routes signing errors to failure/reset; pending-operation registration occurs after successful broadcast. `libs/ledger-live-common/src/hw/actions/transaction.ts` resets interrupted attempts and unsubscribes abandoned observers. `libs/coin-modules/coin-bitcoin/src/observable.ts` has no underlying-promise cancellation teardown, so unsubscribe itself is not proof that the device emitted no signature. The app-result policy matches this practical distinction while Pearl additionally preserves completed bytes and recovery ambiguity in its journal.

## Post-commit host boundary follow-up

Root identified that the host saved its signing attempt before running abort, journal-refresh and freshness checks outside the adapter try/catch. An initial failure in that gap could leave an unsigned attempt reserved. The `sign()` scope now covers those checks with the same catch and tracks whether the adapter was invoked. A shared `cancelOwnedInitialAttempt` helper handles both a definitely pre-invocation error and the adapter's no-result error. It refuses recovery/staged/persisted results and atomically requires the entire original signing record before resetting and discarding it. Concurrent modifications remain reserved. No other host flow was changed by this reviewer.

Companion TypeScript and scoped whitespace checks passed; the then-current actual-main cleanup suite passed **18/18** (`/private/tmp/signing-preinvoke-ui.log`). Dedicated post-commit scheduling cases are independently owned by the product reviewer and are not claimed by that 18-case result. The adapter-only hash manifest remains scoped to its original two files; the parent owns the final integrated host snapshot.
