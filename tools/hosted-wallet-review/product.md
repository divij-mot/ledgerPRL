# Final product and implementation review

10 October 2026. Scope: shared local/hosted wallet behavior, startup, fees/Max, QR, service status, account recovery/display caching, deployment boundaries and current documentation. No production code was changed during this final review, and no personal address, balance, transaction ID or wallet file was read or retained here. This is a bounded AI source/product review, not a professional security audit or exhaustive platform qualification.

## Product contract

- **Local:** `python3 scripts/run-local.py` installs the lockfile, reuses or rebuilds the verified native helper, builds the frontend and starts the existing foreground server. Only this launcher sets the auto-open flag; the successful listen callback opens `http://127.0.0.1:5188/` for desktop Chrome/Edge WebHID. Failed binding never opens a browser. Existing server/helper shutdown remains intact.
- **Hosted:** the same UI uses `/live.html` for Ledger Discover on desktop/Android and `/` for desktop WebHID. The Vercel Hobby project's production origin is `https://pearl-ledger-wallet.vercel.app`; the later [release checkpoint](release.md) records the confirmed deployment and live checks. Hosted operation needs no Mac or native helper. Public Discover listing is a separate Ledger distribution decision.
- Local mainnet account 0 uses actual pinned Pearl wallet/Neutrino/native verifiers and inherits upstream SPV assumptions. Hosted mode trusts the fixed public indexer's chain/history answers, with independent genesis/raw-byte/ownership/consistency checks. It is not browser/native SPV. Both retain Ledger custody and explicit per-payment device review/broadcast.

## Implementation and feature review

The new hosted adapter reuses the existing fixed-endpoint proxy; it adds no second signing engine or general RPC/URL proxy. Its two API entrypoints are two-line wrappers. The added browser cache is a bounded display representation and the QR module is a small local decoder/controller. The only new runtime dependency is lazy-loaded `jsqr@1.4.0`, with no runtime dependencies of its own; its notices/provenance were checked by the deployment reviewer. Existing Ledger views, device adapters, exact-integer wallet, input preflight and durable payment journal remain shared.

The current source implements fresh Fast/Medium/Slow rates for 1/10/25 blocks. Default Standard selects live Medium when available, otherwise explicitly labels the relay-floor fallback. Exact total fee is derived from signed size/input-output shape. Amount/input changes update it; Max reprices its recipient amount with the selected rate; Custom preserves the user-entered total fee. Freshness is checked again inside queued draft persistence. No asynchronous quote changes a prepared canonical payment or signs anything. Local SPV can continue when anonymous fee/status requests fail.

Receive still exposes usable address copy/QR only after device verification. Send's camera/image QR decoder loads on demand, processes local pixels and uploads no image/frame. It validates the current network and exact optional amount, fills only the visible form and preserves separate signing/broadcast. Cancellation closes late camera tracks/bitmaps. The deployment review and retained browser result distinguish real browser decoding/synthetic media from physical-camera or native Android permission tests.

Hosted functions have no application database, account profile, wallet/history cache, cron or analytics integration. Browser account metadata, remembered public-service consent, display cache and durable journal stay local to that client origin/profile. Cached data restores no source validation, completed scan or device approval. A remembered consent choice permits reopening/resync; moving origins/profiles does not transfer reservations automatically.

No unconditional hosted idle full-account polling loop was found. The later bounded pending monitor described below is distinct from both fee polling and full-account polling. The local account-refresh timer remains local-only. Quotes retain a 120-second lifetime. While an unprepared Send Amount step is visible and the app is not busy, one anonymous fee batch refreshes around 105 seconds after the prior request began. Input edits do not reset that absolute deadline; busy work defers it, hidden/other pages make no timer request, and prepared reviews are not repriced. Returning to the visible Amount step performs a cache-aware check. An empty fixture scan was measured by the parent at 46 reads/10,760 response bytes, plus six uncached fee reads/1,003 bytes, combined 3.677 seconds. These are bounded observed fixture costs, not promises for large/active accounts, public traffic, unlimited free-tier usage or uptime. Per-instance request limits are not account-wide abuse quotas. Infrastructure can retain ordinary request metadata; public address queries disclose addresses to the selected service.

Resolved minor status-label issue: `networkHealth` now requires `(account?.account ?? accountIndex) === 0` for the local-sync label, matching local-sync availability. Re-read the corrected predicate and the wallet review’s actual-main regression: nonzero account labels use the public source and no request/signing behavior changes.

The existing `main.ts` state/controller remains large, but this delta does not justify a late architectural rewrite. No new server account service, duplicate custody workflow, gratuitous framework or production demo controls were found in the inspected additions. Settings retains advanced recovery/compatibility controls rather than putting them in the ordinary Send/Receive flow.
