# Recipient validation review

The existing canonical SDK decoder already supplies the requested wallet-address validation. No production change or duplicate regular expression was necessary. This bounded AI source review found no missing length/checksum/network validation in the reviewed recipient flow; it is not physical-device testing or a professional audit.

`packages/sdk/src/keys.ts` checks Bech32m checksum and case rules, the selected network HRP, witness version 1 or 2, canonical conversion padding, and exactly 32 program bytes. P2TR additionally requires a valid secp256k1 x-coordinate; P2MR carries a Merkle root, so curve validation intentionally does not apply. The decoder bounds input at 90 characters; valid supported addresses are consequently 63 characters for `prl` or 64 for `tprl`/`rprl`. Checking those lengths alone would be weaker than decoding. HRP validation distinguishes address prefixes; it cannot distinguish networks that deliberately share an HRP.

The manual recipient Continue handler calls that decoder before moving to the amount screen. Outer whitespace is trimmed; mixed case/internal whitespace are rejected. `parsePaymentQr` uses the same decoder after its URI/scheme/field/amount checks. Transaction preparation independently invokes it in the wallet's payment builder inside the atomic journal update, before reserving a payment. Thus stale or injected preparation events cannot bypass address validation. The reviewed transaction derives its displayed address from the canonical output script.

On device, `preprocess_outputs.c` accepts only 34-byte P2TR/P2MR scripts and validates P2TR curve coordinates. The signed PSBT output script is used by `transaction_display.c`; `format_script`/`get_script_address` reconstruct the address with the compiled coin HRP and Bech32m for nonzero witness versions. The host's input string is not a trusted display label. This portion was source-reviewed, not re-executed on physical hardware.

Added normal-CI test `apps/companion/test/recipient-validation.test.ts`: fifteen malformed forms across mainnet, testnet2 and regtest are rejected by the SDK, raw QR and URI QR paths (empty, shortened, extended, overlong, checksum, mixed case, inner space, wrong HRP, wrong checksum variant, unsupported witness version, 31/33-byte programs, invalid padding invalid P2TR point and foreign URI). The actual bundled main handlers reject all these forms on Continue and a deliberately bypassed Prepare event with zero journal commits or network calls. Valid uppercase P2TR/P2MR with surrounding whitespace produce exactly the expected recipient scripts and amount. Together with the existing QR tests, **6/6 tests passed**. The new file has no TypeScript errors; the concurrent integrated typecheck initially reported an unrelated main.ts refresh-call signature mismatch to the parent. Evidence: `recipient-validation.log` and the scoped source snapshot. No user data, hardware access, real network request or signed transaction was used.
